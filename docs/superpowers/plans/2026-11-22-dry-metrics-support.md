# Multi-Language Duplicate Code & DRY Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add unified, deterministic, resource-efficient Type-1, Type-2, and Type-3 duplicate code detection (both intra-file and cross-file) and DRY metrics across Python, Java, JavaScript/JSX, and TypeScript/TSX in `py-code-health`.

**Architecture:** Single-pass parsing extracts compact typed-array token streams (`array('I')` + `array('B')`, 13 bytes/token) and immediately discards syntax trees before cross-file analysis. A deterministic 64-bit Winnowing + diagonal-deduplicated bidirectional extension engine detects Type-1 (exact), Type-2 (bijective identifier renaming + literal normalization), and contiguous gap-bridged Type-3 clones, while a deterministic SourcererCC frequency-ordered prefix filter over 3-gram function shingles catches scattered Type-3 clones; subsumption and Union-Find clustering emit `DRY-001..DRY-NNN` groups scored inside `Clean Code (15%)` alongside `dry_score`, `duplication_ratio`, `duplicated_loc`, and `DrySummary`.

**Tech Stack:** Python 3.11+ stdlib (`array`, `tokenize`, `ast`, `bisect`, `collections`, `difflib`, `fnmatch`, `re`), existing native Tree-Sitter parsers (`tree-sitter-java`, `tree-sitter-javascript`, `tree-sitter-typescript`), `pytest`.

**Spec:** [specs/005-dry-metrics-support/spec.md](../../../specs/005-dry-metrics-support/spec.md)

## Global Constraints

- **Zero new external runtime dependencies** (`FR-014`, `SC-006`): Python runs purely on stdlib 3.11+ and Java/JS/TS reuse existing Tree-Sitter packages.
- **100% deterministic outputs** (`FR-013`, `SC-005`): repeated runs produce byte-for-byte identical clone group IDs, spans, similarity scores, metrics, and grades.
- **Single-pass parse per file** (`FR-013`): AST/CST trees are discarded immediately after extracting compact token streams.
- **Resource budget** (`SC-004`): 100-file (~15,000 LOC) corpus completes in `< 2.5s` wall-clock with `< 25 MB` peak `tracemalloc` allocation.
- **Comparison buckets & isolation** (`FR-002`, `FR-007`): compare strictly within `python`, `java`, and shared `ecmascript` (`.js`/`.jsx`/`.mjs`/`.cjs` + `.ts`/`.tsx`/`.mts`/`.cts`), and isolate `src ↔ src` from `test ↔ test`.
- **Aggressive source thresholds** (`FR-003`, `FR-004`, Q2): `dry_min_tokens=35`, `dry_min_lines=5`, `dry_type3_similarity=0.70`, `dry_max_gap_tokens=12`, `dry_max_ideal_pct_src=10.0`, `dry_max_penalty_src=35.0`.
- **Self-contained test thresholds** (`FR-004`, `FR-009`, Q3): `dry_min_tokens_test=55`, `dry_min_lines_test=8`, `dry_max_ideal_pct_test=15.0`, `dry_max_penalty_test=25.0`.
- **Clean Code penalty weights** (`FR-009`, Q1): Type-1 `-5.0 pts`, Type-2 `-4.0 pts`, Type-3 `-3.0 pts` (`k - 1` redundant copies intra-file; `1` occurrence per participating file cross-file), plus `-0.5 pts` per `%` of `duplication_ratio` above threshold; `dry_score = clamp_score(100.0 - dry_penalty)`; worst-dimension ceiling applies when `Clean < 75.0`.
- **Exclusions** (`FR-005`, `FR-016`, Q4): skip strictly non-executable declarations (imports, package decls, comments, docstrings, TS `interface`/`type`/ambient decls) and auto-generated files (`@generated`, `DO NOT EDIT`, `AUTO-GENERATED`, `Generated by`, `Code generated by`, Java `@Generated` / `javax.annotation.Generated` / `javax.annotation.processing.Generated` / `jakarta.annotation.Generated`, suffixes `*_pb2.py`, `*_pb2_grpc.py`, `*.generated.*`, `*.gen.*`, `*_pb.*`, `*.pb.*`, plus `dry_exclude_globs`).
- **Self-health quality gate** (`FR-015`, `SC-007`): keep functions `<= 25` LOC, `CC <= 5`, `<= 4` params, files `<= 350` LOC, `<= 5` internal imports, and pass `python scripts/code_health.py scripts --no-git --fail-under 90.0`.
- **Skill mirror parity & docs** (`FR-015`): `skills/code-health/scripts/` must match `scripts/` byte-for-byte; `README.md` must not list penalty points (`test_skill_playbooks.py`).
- **Windows test runner** (avoids CPython 3.15 MSVC build): `uv run --python 3.13 --with pytest --with tree-sitter --with tree-sitter-java --with tree-sitter-javascript --with tree-sitter-typescript pytest ...`.

## Review Focus

1. **Self-overlapping & triple-repeated intra-file blocks + interval-merged `duplicated_loc` cap:** A file repeating the same block 3+ times back-to-back (or nested overlapping Type-1 + Type-3 matches) must never extend a span into itself (`end_a <= start_b`), must suppress redundant lower-type overlaps, and must merge line intervals so `0 <= duplicated_loc <= loc` and `0.0 <= duplication_ratio <= 100.0`. *(Pinned in Task 4 & Task 5)*
2. **Non-bijective Type-2 identifier collision:** Two blocks with identical blind-normalized structure where one reuses an identifier across distinct roles (`x = a + a; y = a + b` vs `p = q + r; s = t + u`) must fail Type-2 1-to-1 bijection verification rather than being labeled `type2`. *(Pinned in Task 5)*
3. **Generated-code false-positive / false-negative boundaries:** Files with `@generated`, `DO NOT EDIT`, `Generated by` in leading 15 lines, Java `@Generated` / `jakarta.annotation.Generated`, or suffixes `*_pb2.py` / `*.generated.ts` / `*.gen.js` / `*.pb.ts` must yield `0` DRY findings and `dry_score = 100.0`, while files mentioning `"generated"` inside a function string literal or containing `@not-generated` must still be scanned normally. *(Pinned in Task 2)*
4. **Mixed-language + JS↔TS + empty/broken file resilience:** Scanning a folder containing Python, Java, `.js`, `.tsx`, an empty `__init__.py`, and a syntactically broken `.ts` file must compare `.js` and `.tsx` in the shared `ecmascript` bucket without cross-comparing Python or Java, skip empty/broken files with `dry_score = 100.0`, and never shift file/token indices. *(Pinned in Task 7)*
5. **Pathological repetitive switch/branch file (quadratic blowup guard) & single-file vs. batch parity:** A file with 80+ repeated switch/if branches must finish within bounded time via posting-list caps (`MAX_BUCKET=64`, `MAX_POSTING=64`), and `analyze_file(path)` must produce identical DRY metrics and scores to `CodeHealthRunner.run([path])`. *(Pinned in Task 5 & Task 6)*
