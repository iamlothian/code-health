# Tasks: Multi-Language Duplicate Code & DRY Metrics Support

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add unified, deterministic, resource-efficient **Type-1 (exact)**, **Type-2 (parameterized / renamed)**, and **Type-3 (near-miss / gapped & scattered)** duplicate code detection (both **intra-file** and **cross-file**) and DRY metrics across **Python**, **Java**, **JavaScript/JSX**, and **TypeScript/TSX** in `py-code-health`.

**Architecture:** Single-pass parsing extracts compact flat typed-array token streams (`array('I')` + `array('B')`, ~13 bytes/token) and immediately discards every AST/CST before cross-file analysis. A 64-bit Mersenne Winnowing index + diagonal-deduplicated bidirectional extension detects Type-1/2 clones (with strict 1-to-1 `KIND_IDENT` bijection) and contiguous gap-bridged Type-3 clones (`<= 12` tokens), while a deterministic SourcererCC frequency-ordered prefix filter over 3-gram function shingles + ordered statement-hash `difflib.SequenceMatcher(..., autojunk=False)` catches scattered Type-3 clones. Subsumption, Union-Find clustering (`DRY-001..DRY-NNN`), and merged-interval counting score DRY penalties inside `Clean Code (15%)` alongside standalone `dry_score`, `duplication_ratio`, `duplicated_loc`, and `DrySummary` outputs.

**Tech Stack:** Python 3.11+ stdlib (`array`, `ast`, `bisect`, `collections`, `dataclasses`, `difflib`, `fnmatch`, `math`, `re`, `tokenize`), existing native Tree-Sitter grammars (`tree-sitter-java`, `tree-sitter-javascript`, `tree-sitter-typescript`), `pytest>=8.0.0`.

**Input:** Design documents from `specs/005-dry-metrics-support/`  
**Prerequisites:** [spec.md](./spec.md), [plan.md](./plan.md), [research.md](./research.md), [data-model.md](./data-model.md), [cli-contract.md](./contracts/cli-contract.md), [dry-engine-contract.md](./contracts/dry-engine-contract.md), [quickstart.md](./quickstart.md), and companion blueprint [2026-11-22-dry-metrics-support.md](../../docs/superpowers/plans/2026-11-22-dry-metrics-support.md)

## Global Constraints

- **Zero new external runtime dependencies** (`FR-014`, `SC-006`): core Python DRY analysis uses stdlib 3.11+ only; Java/JS/TS reuse existing Tree-Sitter packages.
- **100% deterministic outputs** (`FR-013`, `SC-005`): repeated runs emit identical clone group IDs (`DRY-001..DRY-NNN`), line spans, similarity scores, metrics, and grades.
- **Single-pass parse per file** (`FR-013`): discard AST/CST trees immediately after extracting `FileReport` and `FileTokenStream`.
- **Resource budget** (`SC-004`): 100-file (~15,000 LOC) corpus completes in `< 2.5s` wall-clock with `< 25 MB` peak `tracemalloc` allocation.
- **Comparison buckets & role isolation** (`FR-002`, `FR-007`): compare strictly within `python`, `java`, and shared `ecmascript` (`.js`/`.jsx`/`.mjs`/`.cjs` + `.ts`/`.tsx`/`.mts`/`.cts`), isolating `src ↔ src` from `test ↔ test`.
- **Aggressive source thresholds** (`FR-003`, `FR-004`, Q2): `dry_min_tokens=35`, `dry_min_lines=5`, `dry_type3_similarity=0.70`, `dry_max_gap_tokens=12`, `dry_max_ideal_pct_src=10.0`, `dry_max_penalty_src=35.0`.
- **Self-contained test thresholds** (`FR-004`, `FR-009`, Q3): `dry_min_tokens_test=55`, `dry_min_lines_test=8`, `dry_max_ideal_pct_test=15.0`, `dry_max_penalty_test=25.0`.
- **Clean Code penalty weights** (`FR-009`, Q1): Type-1 `-5.0 pts`, Type-2 `-4.0 pts`, Type-3 `-3.0 pts` (`k - 1` redundant copies intra-file; `1` occurrence per participating file cross-file), plus `-0.5 pts` per `%` of `duplication_ratio` above threshold; `dry_score = clamp_score(100.0 - dry_penalty)`; worst-dimension ceiling applies when `Clean < 75.0`.
- **Exclusions** (`FR-005`, `FR-016`, Q4): skip strictly non-executable declarations (imports, package decls, comments, docstrings, TS `interface`/`type`/ambient decls) and auto-generated files (`@generated`, `DO NOT EDIT`, `AUTO-GENERATED`, `Generated by`, `Code generated by`, Java `@Generated` / `javax.annotation.Generated` / `javax.annotation.processing.Generated` / `jakarta.annotation.Generated`, suffixes `*_pb2.py`, `*_pb2_grpc.py`, `*.generated.*`, `*.gen.*`, `*_pb.*`, `*.pb.*`, plus `dry_exclude_globs`).
- **Self-health & modularity gates** (`FR-015`, `SC-007`): keep functions `<= 25` effective LOC, `CC <= 5`, `<= 4` params, files `<= 350` LOC, internal imports `<= 5`, and Grade A (`>= 90.0`).
- **Skill mirror & playbook hygiene** (`FR-015`): `skills/code-health/scripts/` must match `scripts/` byte-for-byte; `README.md` must list zero penalty points (`tests/unit/test_skill_playbooks.py`).

## Review Focus

1. **Self-overlapping & triple-repeated intra-file blocks + interval-merged `duplicated_loc` cap:** Repeating the same block 3+ times back-to-back (or nesting Type-1 + Type-3 matches) must enforce `end_a <= start_b`, suppress redundant lower-type overlaps, and merge line intervals so `0 <= duplicated_loc <= loc` and `0.0 <= duplication_ratio <= 100.0` *(pinned in `T010`, `T013`)*.
2. **Non-bijective Type-2 identifier collision:** Identical blind-normalized blocks where one reuses an identifier across distinct roles (`x = a + a; y = a + b` vs `p = q + r; s = t + u`) must fail Type-2 bijection verification *(pinned in `T013`)*.
3. **Generated-code boundary accuracy:** Header markers (`@generated`, `DO NOT EDIT`, `Generated by` in leading 15 comment lines), Java `@Generated`/`jakarta.annotation.Generated`, and suffixes (`*_pb2.py`, `*.generated.ts`, `*.gen.js`, `*.pb.ts`) skip DRY checks (`dry_score=100.0`), while `"generated"` in string literals or `@not-generated` are still scanned *(pinned in `T004`)*.
4. **Mixed-language + JS↔TS + empty/broken file resilience:** Scanning `.py`, `.java`, `.js`, `.tsx`, empty `__init__.py`, and syntax-invalid `.ts` compares `.js`↔`.tsx` in `ecmascript`, isolates `python`/`java`, and skips empty/broken files with `dry_score=100.0` *(pinned in `T031`)*.
5. **Pathological 80-branch file cap & single-file vs. batch parity:** An 80+ branch file completes well under budget via `MAX_BUCKET=64` / `MAX_POSTING=64` (`< 0.5s`), and `analyze_file(path)` produces identical DRY metrics and scores to `CodeHealthRunner.run([path])` *(pinned in `T013`, `T024`)*.
